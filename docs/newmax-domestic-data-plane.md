# NewMax 国内数据面

## 概述

国内数据节点复用生产渠道、token 和消费日志数据库，只在国内接收模型请求并直连上游；不独立运行钱包、迁移或共享文件型生图任务。

## 组件关系

- 美国 control 与 APISIX 继续管理唯一钱包和消费者配置。
- 京东云 APISIX 经 WireGuard 订阅相同 etcd `/apisix` 配置，`new-api:3000` 在各自 Docker 网络解析为本地节点。
- 京东云 New API 以 `NODE_TYPE=slave` 连接隧道内生产 PostgreSQL，使用本机 Redis。
- 生图、音视频等非聊天端点继续回源美国，避免跨节点读取本地任务文件。

## 关键设计决策

`IMAGE_TASK_WORKER_ENABLED=false` 显式禁用当前节点的全部图片任务后台行为。检查必须在 `sync.Once`、目录初始化、陈旧任务隔离、排队超时、任务领取和结果清理之前执行。未设置时默认启用，以保持现有单节点行为；不能用 `IMAGE_TASK_WORKERS=0` 代替，它历史上被规范化为至少一个 worker。

共享配置存储替代向两个 Admin API 双写：创建、轮换、熔断、恢复和删除均只有一个配置事实来源，不引入部分成功后密钥分裂的问题。两地限流计数仍为各自本地计数。

## 数据流

国内聊天请求 → 京东云 Nginx（转发前健康门禁）→ 本机 APISIX → 本机 New API → 国内上游；认证配置经隧道同步，消费日志写回同一生产库，由原对账器处理。

健康失败仅在请求体交给模型节点前回源。禁止收到模型失败响应后自动重放 POST，以免重复计费。文件型媒体任务始终回源原节点。

## 已知问题 / 技术债

- PostgreSQL 和配置存储仍依赖跨境隧道，但不传模型请求正文。
- 未部署共享文件存储，不支持跨地区图片异步任务执行。
- 显式禁用开关需随国内节点的新二进制部署；旧镜像设置同名环境变量没有效果。
